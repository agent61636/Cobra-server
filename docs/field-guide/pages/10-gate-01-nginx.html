nginx is the bouncer's doorframe. It holds the wildcard certificate, answers on 443, reads the name you typed, asks Authelia whether you may come in, and then hands your request to the right app, on the gate or across the LAN on the SGIN.

It is the only container in World 1 with a door to the outside: the gate pod publishes just ports 80 and 443, and both belong to nginx. Every other gate app (Authelia on 9091, Vaultwarden on 8222, Paperless on 8000 and the rest) listens on 127.0.0.1 inside the pod, where only nginx can reach it. That is the whole security model in one sentence: if nginx doesn't send you there, you can't get there.

Port 80 does exactly one thing: it answers 301, go to https. OPNsense doesn't even forward 80 from the internet, because the certificate comes through Porkbun's DNS, not a web challenge. So from outside, 443 is the island's only open TCP door, and nginx is standing in it.


        
CLAUDE-VIPERScanners that knock on your bare IP get nothing. Not a page, not even a certificate. The catch-all server refuses the TLS handshake, so they never learn the name songofeo.com.

THE AUTH_REQUEST TRICK

        
Every guarded location / carries one line: auth_request /internal/authelia/authz;. Before nginx forwards anything, it makes a tiny side request to Authelia at 127.0.0.1:9091/api/authz/auth-request, with the original URL and your cookie.

        
200 means go ahead. 401 becomes a 302 to gate.songofeo.com with your page attached, so after signing in you land right back where you were.

        
On the floors, Authelia also tells nginx who you are, and nginx passes that on as the Remote-User header. Navidrome trusts that header from 10.6.9.10 only, so you don't log in twice.

      

      
TWO MAPS, ONE FILE

        
map $host $station turns a floor name into an address (music. to :4533, books. to :13378...). map $host $protected does the same for the admin apps on 127.0.0.1. Adding a floor is mostly one line in a map plus the name in that block's server_name.

      

    

    

      
WHAT IT SETS ON EVERY REQUEST

        
    
          
  • HSTS: "never use plain http here" for a year
    • 
          
  • X-Forwarded-For = $remote_addr: the gate is the first proxy, so the visitor can't smuggle in a fake address
    • 
          
  • Remote-User "": a visitor's own Remote-User header is always wiped
    • 
          
  • Websockets: Upgrade and Connection headers, for Uptime Kuma, MeTube and Jellyfin
    • 
          
  • No size limit (client_max_body_size 0) for RomM and Audiobookshelf uploads
    • 
        

      

      
RATE LIMITS

        
Two buckets per visitor address: media at 50 requests a second (burst 300) because a library page loads dozens of covers, and perip at 10 a second (burst 50) for the sign-in and admin apps. Over the limit you get 429, not a ban.

      

      
STREAMING STRAIGHT THROUGH

        
On the floors and tv., proxy_buffering off streams video, audio and ROM downloads straight through instead of spooling them onto the gate's small disk, and timeouts are 1 hour so a long movie or a websocket doesn't get cut.

      

    

  






  
TIPS & TRICKSPOWER-UPS

  

    

      
PRO TIP: RELOAD, DON'T RESTART

        
After editing songofeo.conf, test it and reload in place. A reload keeps every open stream playing; a bad config is refused and the old one stays live.

      

      
CODES

        GATE · podsvc
        podman exec nginx nginx -t
        Must say "syntax is ok" and "test is successful".
        podman exec nginx nginx -s reload
        Loads the new config with no downtime.
      

      
PRO TIP: CHECK ALL NAMES

        
check.sh asks the gate's own nginx for every hostname and prints OK, NOTE or FAIL with what to look at. From the gate it's the view from outside the house, so floors must bounce you to the sign-in.

      

      
CODES

        GATE · eels or podsvc
        ~podsvc/cobra-server/scripts/podman/gate/check.sh

JOE SABOTAGE REPORT

      
Found in the footlockers, stepped on during the build, or flagged in manual part 5.4.

    

  

  

    

      
THE OPEN BLOCK

        
A server or location without its own auth_request line is open to anyone who can reach the gate. There is no global "protect everything" switch.Copy a whole protected block, auth location included, every time you add a name. Then run check.sh.

      

      
THE VANISHING HEADERS

        
A location that sets even one proxy_set_header drops all the inherited ones. Same with add_header: one CORS header in station-cors.inc can silently delete HSTS from the floors.Re-list every header in that location (the config does). Test HSTS with curl, below.

      

      
THE MISSING INCLUDE

        
A plain include of a file that doesn't exist stops nginx from starting, which takes down every floor and the sign-in.The config uses station-cors*.inc, a pattern, so a missing file just matches nothing.

      

      
THE 403 LOCKOUT

        
New name in nginx, but forgot Authelia? Authelia's default_policy: deny refuses it, so you get 403. That's the safe way to fail.Add an access_control rule for the name and restart Authelia.

      

    

    

      
THE 127.0.0.1 IMPOSTOR

        
If every log line starts with 127.0.0.1 or 10.0.2.x, the pod isn't on pasta. Then everyone looks local: the home bypass, Vaultwarden's LAN rule and Jellyfin's logs all break.Stop and check podman info --format '{{.Host.RootlessNetworkCmd}}' says pasta.

      

      
THE LOW-PORT WALL

        
Rootless podman can't bind 80/443 until the kernel allows it. And the old pod.sh called sysctl, which isn't on podsvc's PATH on Debian (fixed in PR #44: it reads /proc now).As eels, the sysctl.d line from part 5.2 sets ip_unprivileged_port_start=80.

      

      
THE CATCH-ALL HIJACK

        
Three old OPNsense forwards pointed at the SGIN, one of them any/any. That catch-all swallowed WireGuard's UDP too. They're disabled now; only WAN TCP 443 to 10.6.9.10 is live.Destination NAT must show exactly one enabled rule. Never forward to 10.6.9.20.
