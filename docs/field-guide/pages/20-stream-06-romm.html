RomM is the browser arcade. It catalogs every ROM by platform, fetches box art and titles, and with EmulatorJS built in, lets anyone you've signed in play right in their browser. Press start on a laptop, a tablet, even a phone.

The trick: the game runs in the player's browser, not on the server. The SGIN only hands out files, so ten people playing ten games barely tickle its CPU. RomM keeps its catalog in a MariaDB database (next chapter) and its covers and settings on the SGIN's SSD.

The ROMs live on dock1b, in dock1b/roms. Their main copy is on the cabinet, cobra-arcade's D:\Roms, and the cabinet sends them up every night, so the web arcade keeps working while the cabinet sleeps.

TWO ARCADES, ONE ROM PILE

    

      
The cabinet (OptiPlex, LaunchBox and RetroArch) plays from D:\Roms with the Tankstick. Its saves live on the cabinet.

      
The web arcade (RomM and EmulatorJS) plays the nightly copy on dock1b in any browser. Its saves live in RomM, per user.

ONE FOLDER PER PLATFORM

        
RomM expects roms/<platform>/: roms/snes, roms/n64, roms/arcade and so on. Each folder shows up as a platform after a scan. The cabinet's own folder names don't always match RomM's, so the cabinet script 03-roms-map.ps1 writes a folder map, and romm-platforms.sh adds it to RomM's config.yml under system:.

      

      
ONE-WAY TRAFFIC

        
The nightly copy runs cabinet to SGIN only (robocopy /E /XO: adds and updates, never deletes). New ROMs go onto the cabinet's D:\Roms; the next night they appear on dock1b, then a RomM scan picks them up.

      

      
WHY RomM MAY WRITE

        
Unlike the read-only media apps, RomM's roms folder is mounted writable, with keep-groups so it keeps podsvc's media group. No :Z on it, because Samba shares the same folder for the cabinet's copy.

SECRETS, NOT SCRIPTS

        
The database password and RomM's auth key are made once and kept as podman secrets (romm-db-password, romm-auth-secret) when built by the scripts. They never appear in the script or in podman inspect. In Quadlet mode they're in the 600-protected romm*.container files instead.

      

      
THE SCOREBOARD IS ELSEWHERE

        
The hiscore board at scores.songofeo.com runs on the gate, not here. RomM is just the arcade floor.

      

    

  

  
THE NIGHTLY COPY

    
On the cabinet, 02-nightly.ps1 sets up the nightly job (run it once with -RunNow for the first copy). It logs to C:\Cobra\nightly-copy.log and writes === end when done. The copy logs in to the SGIN's Samba as user arcade, saved once with cmdkey.

TIPS & TRICKSPOWER-UPS

  

    

      
PRO TIP: COVERS + NAMES

        
Free metadata keys (IGDB through Twitch, ScreenScraper, SteamGridDB) give RomM box art and proper titles. With the scripts, put them in ~/.config/cobra/romm.env as IGDB_CLIENT_ID=... lines and rerun ./romm.sh; with Quadlets, as Environment= lines in romm.container.

      

      
PRO TIP: NETPLAY

        
Netplay lets two browsers play one game together (WebRTC). romm.sh writes it switched on in config.yml. Friends outside the house usually also need a TURN relay; RomM's EmulatorJS docs list free ones under ice_servers.

      

      
PRO TIP: BIOS FILES

        
Some systems won't boot without BIOS files. RomM → the platform → Firmware → upload. Several files for one system? Zip them together first.

      

      
PRO TIP: ONE USER PER PLAYER

        
Administration → Users. Each player's saves and save states then stay their own.

JOE SABOTAGE REPORT

      
From manual 3.8b, the arcade runbook and the scripts' own warnings.

    

  

  

    

      
THE WRONG-WAY ROM

        
ROMs dropped straight into \\cobra-stream\roms never reach the cabinet: the copy only runs cabinet to SGIN.Add ROMs on the cabinet in D:\Roms\<platform>.

      

      
THE TOO-BIG PILE

        
dock1b is a 1 TB drive; D:\Roms on the 4 TB drive could outgrow it.The nightly script stops by itself if D:\Roms is bigger than dock1b's free space. Check its log.

      

      
THE FORGOTTEN PASSWORD

        
RomM's database already exists with an old password, and a fresh run makes a new one: RomM can't log in to its own database. romm-up.sh stops rather than guess.Give the old values once: ROMM_DB_PASSWORD=... ROMM_AUTH_SECRET=... in front of the command.

      

      
THE PUBLISHED-PORT GAP

        
No PublishPort=8080:8080 in stream.pod, and RomM answers nobody.Add the line, daemon-reload, restart stream-pod. romm-up.sh checks it for you.

      

    

    

      
THE SAVE SPLIT

        
Beat a level on the cabinet, open the same game in the browser: no save. They share ROMs, never saves, and browser netplay can't join a RetroArch netplay game.Pick one place per playthrough.

      

      
THE LONELY NETPLAY

        
Netplay works at home but a friend across town never connects.Add a TURN relay under ice_servers in config.yml.

      

      
THE DOUBLE CONFIG

        
romm-platforms.sh refuses if config.yml already has a platforms: or system: section, so it never writes a duplicate.Paste the map in by hand with nano, under the existing section.

      

      
THE EMPTY SCAN

        
Scan before the first nightly copy and RomM finds nothing.Watch C:\Cobra\nightly-copy.log on the cabinet for === end, then Scan.
