Postgres is the database Paperless keeps its brain in: every document's title, date, tags, correspondent, owner and notes, plus the users and settings. You never open it. You'd only notice it if it stopped, because then Paperless stops too.

It runs in its own container in the gate pod, listening on 127.0.0.1:5432 where only its neighbours can reach it. Its whole world is one folder, /srv/gate/postgres, mounted into the container as /var/lib/postgresql/data. The database is called paperless, and so is its user.

The image is pinned to version 16 (postgres:16). AutoUpdate=registry pulls new 16.x releases (bug and security fixes), but never jumps to 17 by itself, and that's on purpose: a database folder made by 16 can't be opened by 17 without an upgrade step.


        
CLAUDE-VIPERThe scanned files themselves aren't in here. They sit in Paperless's media folder. Postgres holds the card catalogue that says what each one is.

THE PASSWORD HANDSHAKE

        
Postgres sets the paperless user's password once, the first time it starts with an empty folder. Paperless must then use the same one. The manual generated it as PGPW and wrote it into both Quadlet files; the scripts keep it as the podman secret paperless-db-password.

        
Change it later in one place only and Paperless can't log in. Moving from Quadlets to scripts? Hand the old value to paperless.sh once, as PAPERLESS_DB_PASSWORD=....

      

      
WHO OWNS THE FILES

        
Inside the container Postgres runs as user 999. Rootless podman maps that to a high "sub-UID" on the gate, not to podsvc. So on the gate, ls -ln /srv/gate/postgres shows a big number as owner. That's correct, and it's exactly what chown -R wrecks.

      

    

    

      
READY OR NOT

        
pg_isready is Postgres's own "are you up?" check. paperless.sh waits on it for up to two minutes before starting Paperless. With Quadlets, After=postgres.service orders the start, and Paperless retries on its own.

      

      
BACKUP

        
/srv/gate/postgres is inside VM 110, so the nightly snapshot backup to PBS carries it. Paperless's own exporter (previous chapter) is the app-level copy. A pg_dump gives a third, plain-SQL copy.

      

      
WHY NOT SQLITE?

        
Paperless could use a single SQLite file, but its background workers write at the same time as the web page. Postgres handles that crowd without locking up.

TIPS & TRAPSCODES + SABOTAGE

  

    

      
CODES

        GATE · podsvc
        podman exec postgres pg_isready -U paperless
        "accepting connections" = healthy.
        podman logs --tail 30 postgres
        podman exec -it postgres psql -U paperless
        A SQL prompt. \dt lists tables, \q quits. Look, don't touch.
      

      
PRO TIP: A SQL BACKUP

        
pg_dump writes the whole database as one SQL file. Put it in Paperless's export folder so it sits with the rest.

      

      
CODES

        GATE · podsvc
        podman exec postgres pg_dump -U paperless -f /tmp/paperless.sql paperless
        podman cp postgres:/tmp/paperless.sql /srv/gate/paperless/export/
      

      
PRO TIP: SEE THE OWNER

        
podman unshare ls -ln /srv/gate/postgres shows ownership as the container sees it: it should say 999.

      

    

    

      
THE CHOWN DISASTER

        
The manual's chown -R podsvc: /srv/gate is for the first setup only. Re-run later, it handed Postgres's files to podsvc, and Postgres (999) could no longer read global/pg_filenode.map.podman unshare chown -R 999:999 /srv/gate/postgres, then restart postgres and paperless.

      

      
THE BIG JUMP

        
Changing the image to postgres:17 on an existing folder makes Postgres refuse to start: the data was written by 16.Stay on 16. A major upgrade means a dump, a fresh folder, and a restore. Plan it, don't stumble into it.

      

      
THE PASSWORD SPLIT

        
Postgres only reads POSTGRES_PASSWORD on an empty folder. Editing it later changes nothing inside the database, but Paperless starts using the new one.Leave both values alone.

      

      
THE EXPOSED PORT

        
5432 must never appear in the gate's listening ports.ss -tlnH as eels: only 22, 80, 443 and 9090.
