Every arcade needs someone keeping the books. romm-db is a MariaDB database server, and it remembers everything RomM knows: which games exist on which platform, their titles and metadata, the users, and who played what.

It has no web page and no public name. It sits in the stream pod, listening on MariaDB's port 3306 on 127.0.0.1, which only containers inside the pod can reach. That port is not in the pod's published list, so nothing on the LAN can talk to it, let alone the internet.

Its files live in /srv/stream/romm/db on the SGIN's SSD. The ROMs themselves aren't in it: the database holds the catalog, the drive holds the games.

HOW IT GETS ITS PASSWORDS

        
On the very first start, with an empty db folder, MariaDB creates the romm database and user with the password it's given (MARIADB_PASSWORD) and sets the root password. After that, the password is stored inside the database files. Changing the variable later doesn't change it.

        
With the scripts, the passwords come from podman secrets, handed in as environment variables only inside the container. With the manual's Quadlets, they're written into romm-db.container, which is chmod 600.

      

      
THE HEALTH CHECK

        
The script gives the container a health check (healthcheck.sh --connect --innodb_initialized) and waits for healthy before starting RomM. In Quadlet mode, romm.container says Requires=romm-db.service and After= it instead, so systemd starts the database first.

      

      
WHY NOT THE GATE'S DB?

        
The gate's Postgres belongs to Paperless and lives on another machine. RomM wants MariaDB or MySQL, and keeping its database next to it in the same pod means the arcade never depends on the gate being up.

      

    

    

      
TIPS & TRICKS

      
CODES

        SGIN · podsvc
        podman ps --filter name=romm
        romm-db and romm, both Up.
        podman logs --tail 30 romm-db
        podman secret ls
        Scripts mode: lists the secret names, never the values.
        podman secret inspect --showsecret --format '{{.SecretData}}' romm-db-password
        Prints the password. Only when you need it, and not on a shared screen.
      

      
PRO TIP: A SPARE COPY

        
A dump is a plain-text copy of the whole database you can restore from. Inside the container the password is already in the environment, so the dump command doesn't need you to type it:

      

      
CODES

        SGIN · podsvc
        podman exec romm-db sh -c 'mariadb-dump -u romm -p"$MARIADB_PASSWORD" romm' > ~/romm-db.sql
        Writes ~/romm-db.sql in podsvc's home. Move it to dock1a/backups if you want it kept.
      

      
PRO TIP: IT'S IN THE BACKUP

        
/srv/stream is the SGIN's app data. Back it up with RomM stopped (or use a dump), so the database files are consistent.

JOE SABOTAGE REPORT

      
Includes a trap that hit the gate's Postgres for real on 6 November 2026.

    

  

  

    

      
THE CHOWN DISASTER

        
On the gate, re-running a chown -R podsvc: /srv/gate after Postgres had made its files broke them ("pg_filenode.map: Permission denied"). Rootless database files belong to a mapped user ID inside the container, not podsvc. The same move on /srv/stream would break romm-db.Never chown -R a database folder. If it happened, repair from podsvc with podman unshare chown -R to the database's own user (999:999 for these official images).

      

      
THE NEW-PASSWORD TRAP

        
Rebuild RomM with fresh random passwords while romm/db still holds the old database: the database keeps the old password, RomM sends the new one, and gets "access denied".Reuse the old values (ROMM_DB_PASSWORD=... ./romm.sh), read from the old romm.container or the saved secret.

      

      
THE PERMISSION LOOP

        
A container that keeps restarting with Permission denied in its log: the image switched to a non-root user inside, and its folder belongs to someone else.Manual 3.8's last bullet: find the user with podman exec <name> id and add UserNS=keep-id:uid=...,gid=....

      

    

    

      
THE BIG-JUMP UPGRADE

        
The image is pinned to mariadb:11, so updates stay within MariaDB 11. Changing the tag to a new major version blindly can leave the files needing an upgrade step.Dump first, read the release notes, then change the tag.

      

      
THE PUBLISHED DATABASE

        
Adding 3306 to the pod's published ports "to look at it from the-box" would put a database on the LAN.Leave it out. Use podman exec -it romm-db mariadb -u romm -p romm on the SGIN instead.

      

      
THE IMPATIENT START

        
RomM started before the database was ready fails its first connection. Usually it just retries.The script waits for healthy; in Quadlet mode systemd's After= orders them. Still stuck: podman logs romm-db.

      

      
THE PASSWORD ON SCREEN

        
--showsecret prints the real password in the terminal and in scrollback.Run it only when needed, then clear the screen. Keep a copy in Vaultwarden.
