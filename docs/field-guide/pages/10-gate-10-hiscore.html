hiscore is the island's own arcade scoreboard, written for Cobra Island and kept in this repo (apps/hiscore). Whenever a game on the cabinet saves a new high-score file, it's uploaded within seconds; the board at scores.songofeo.com lists every game, newest score first, and keeps every version byte for byte.

It's a small Python app that uses only Python's standard library, so there's no image to build: the stock python:3.13-slim image runs it straight from /srv/gate/hiscore-app. Its data, every .hi file ever received plus the index hiscore.db, lives in /srv/gate/hiscore.

Status: part 7 of the manual is written and the app is tested, but the board isn't running on the gate yet. check.sh shows scores. as NOTE ("no server block yet"), and Homepage's High scores tile stays red until it is. It comes after the cabinet build.

TWO UPLOADERS

        
The LaunchBox plugin uploads the moment a game closes and adds what only LaunchBox knows: the proper title and platform. The hiscore agent checks every 15 seconds, catches games started outside LaunchBox, and retries while the network is down. Both upload; the server ignores a file it already has.

      

      
THE API KEY

        
python -m hiscore hash-key cabinet prints a key and a line for keys.txt. The cabinet keeps the key; the server keeps only its hash in /srv/gate/hiscore/keys.txt. To replace a key, make a new one and swap the line.

      

      
WHAT'S IN A .HI FILE

        
A copy of the game's memory, not text. Reading it needs a per-game definition: hi2txt on the cabinet through the plugin, or a decoder on the server (HISCORE_DECODER). Games nothing can read still list, as "Score table saved".

      

    

    

      
LOCKED-DOWN NGINX

        
Its server block opens only three paths without Authelia: /upload/ (PUT only, 256 KB max), /public/ and /screen (GET only). Everything else, the board itself, needs the sign-in. Viewers need a password, not TOTP.

      

      
THE ARCADE SCREEN

        
/screen cycles through each game's top scores with a ticker of the latest. The server lets songofeo.com show it in a frame and no other site. Options: ?embed=1, ?seconds=8, ?game=galaga, ?demo=1.

      

      
PUBLIC OR NOT

        
With HISCORE_PUBLIC=1 (the Quadlet in part 7.3 sets it), anyone can read titles, initials and scores, so the screen on songofeo.com works for visitors. Without it, visitors see demo scores and only signed-in people see real ones.

TIPS & TRICKSPOWER-UPS

  

    
      
PRO TIP: ONE GAME ONLY

        
/screen?game=galaga shows a single game's table: perfect for a tournament night on the marquee.

      


      
PRO TIP: IS IT ALIVE?

        
/healthz answers {"ok": true}. The image has no curl, so ask with Python from inside.

      

      
CODES

        GATE · podsvc
        podman exec hiscore python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8090/healthz').read())"
        podman logs --tail 30 hiscore
        systemctl --user restart hiscore
      

      
PRO TIP: REAL TITLES

        
Put a titles.tsv in /srv/gate/hiscore/, one romname, tab, Title line per game, and restart. ROM names become proper names even without the plugin.

      

      
PRO TIP: TRY THE SCREEN

        
On THE-BOX, open https://scores.songofeo.com/screen?demo=1 to see attract mode with made-up games before any real score exists.

      

    

    

      
PRO TIP: A NEW KEY

        
Run the hash-key command from the app folder. It prints the key (into Vaultwarden it goes) and the line for keys.txt.

      

      
CODES

        GATE · podsvc
        cd /srv/gate/hiscore-app
        podman run --rm -v "$PWD":/app:ro,Z -w /app docker.io/library/python:3.13-slim python -m hiscore hash-key cabinet
      

      
PRO TIP: UPDATE THE APP

        
New version in the repo? Copy apps/hiscore/hiscore to the gate (scp from THE-BOX), replace /srv/gate/hiscore-app/hiscore, restart. With the run scripts, hiscore.sh copies it from a repo checkout by itself.

      

      
PRO TIP: DOWNLOAD A RECORD

        
Every card has a download link for each version. Lost the cabinet's disk? Your scores aren't lost.

      

      
PRO TIP: SCORE THE CHECK

        
A bad key must get 401: curl -X PUT -H "Authorization: Bearer wrong" --data-binary x https://scores.songofeo.com/upload/test/x.hi from THE-BOX.

      

    

  

  

  
WHERE THE FILES LAND

    
/srv/gate/hiscore/raw/fbneo/galaga.hi/<time>-<hash>.hi

    
One folder per system and game, one file per version, named by when it arrived and its fingerprint. hiscore.db next to raw/ is the index of titles and tables. All of it is inside VM 110, so the nightly backup to PBS covers every score ever set.

  






  

    

    

      
JOE SABOTAGE REPORT

      
The board isn't live yet, so these are the traps waiting for launch day.

    

  

  

    

      
THE MISSING KEY FILE

        
No keys.txt, or a wrong line in it, and every cabinet upload gets 401. The board stays empty.One line: cabinet, a space, the hash. Mode 600. The script warns when the file is empty.

      

      
THE DEMO-ONLY SCREEN

        
hiscore.sh doesn't set HISCORE_PUBLIC; the part 7.3 Quadlet does. Run by script and visitors see demo scores on songofeo.com/arcade.Script mode: put HISCORE_PUBLIC=1 in ~/.config/cobra/hiscore.env and rerun.

      

      
THE FORGOTTEN RULE

        
Add the nginx block but not Authelia's rule, and scores. answers 403: default deny.Add scores.songofeo.com with policy: one_factor, then restart nginx and authelia.

      

    

    

      
THE NO-DNS NAME

        
Without a Porkbun CNAME, scores. works at home (the Pi-holes answer every name) but not from outside.CNAME scores to gate.songofeo.com.

      

      
THE BIG UPLOAD

        
nginx caps /upload/ at 256 KB, matching the server's default. Some odd file bigger than that is refused.That's on purpose: .hi files are tiny. Raise both limits only if a real game needs it.

      

      
THE UNREADABLE CARD

        
A card says "Score table saved" but shows no initials. Nothing can read that game's file yet.hi2txt on the cabinet (7.6) or a server decoder (7.8). The file is kept either way.
